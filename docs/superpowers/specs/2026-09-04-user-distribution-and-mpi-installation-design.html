概述与证据

ATST-Tools 已具备 README、中文用户指南、示例学习路径、CLI/API/YAML reference 与功能状态矩阵；问题不是缺少资料，而是不同分发渠道不能保证把用户送到同一份资料。GitHub 主仓为 QuantumMisaka/atst-tools，Gitee 镜像为 jamesmisaka/atst-tools，两者均以 main 为当前分支并在本设计确认时指向同一提交。镜像由维护者从 GitHub 手动拉取同步；它不拥有专属 README、分支策略或同步代码。PyPI 复用 README 时会把仓库相对链接解析为 PyPI 子路径，致使用户指南、示例和 reference 链接 404。

审查还确认：用户入口（README、docs/index.md、docs/user/、examples/README.md）未写入 SAI 分区、QOS 或作业命令；SAI 特定事实已经主要位于维护者操作指南和验证报告。这个分层应保留。当前待修正的事实漂移包括错误的源码 clone URL、USER_GUIDE_CN.md 仍称 2.2.1、2.2.3 release notes 的 Compatibility 版本仍为 2.3.0，以及 atst-cli skill 的旧分支叙述。

另外，mpi4py 已经是 [parallel] optional extra，而非默认依赖。用户反馈的 wheel 加载崩溃属于外层 MPI launcher、动态库和 mpi4py 构建 ABI 不一致风险；不应以拆分两个 ATST 包来解决，而应明确串行默认档与 image-parallel 档，并在后者给出通用的站点 MPI 预检和恢复路径。

目标与非目标

目标

  • 用户从 GitHub、Gitee 或 PyPI README 出发，在一次点击内到达中文用户指南和示例入口。
  • 明确 GitHub、Gitee 与 PyPI 的权威边界，避免镜像被误认为可接受 issue、PR 或发布的规范源。
  • 让默认安装保持纯串行、无需安装或加载 mpi4py；仅 image-level NEB/AutoNEB 用户进入 MPI 安装路径。
  • 使面向用户的文档保持站点无关，同时保留 SAI 作为维护验证证据与维护操作环境。
  • 用自动检查防止版本、仓库 URL、README 链接和安装契约再次漂移。

非目标

  • 不新建独立文档站，不建立第二套文档内容，也不改变 Markdown 文档的本地规范源地位。
  • 不创建 atst-tools-serial、atst-tools-mpi 或 vendor MPI 变体包。
  • 不把 SAI 的 module、partition、QOS、job ID 迁入用户指南；也不删除已有验证报告中的历史事实。
  • 不在本设计中配置 Gitee 认证、webhook、同步机器人、镜像专属 README/代码或发包凭据；镜像继续由维护者手动拉取同步。

需求

ID要求验收信号
R1在同一份 README 与相关维护文档中写明 GitHub 主仓、Gitee 手动只读镜像、PyPI 包分发的职责。三处职责无矛盾；同一 README 并列 GitHub/Gitee 链接并将协作入口指向 GitHub；无 Gitee 专属文件或代码。
R2README 第一屏或 Quick Start 前提供 GitHub/Gitee 的绝对“用户指南”“示例”入口；仓库内现有相对链接可保留。从 PyPI README 点击两个入口均非 pypi.org/project/.../docs/...，并到达相应 main 文档。
R3所有面向用户的源码安装命令使用真实主仓 URL https://github.com/QuantumMisaka/atst-tools.git；镜像下载方式另列为可选通道。对 README 与用户指南运行 URL/文本回归检查；旧 deepmodeling/atst-tools 不再出现在活跃用户文档。
R4用户安装页提供三档：Serial default、DP optional、Image-parallel optional；明确默认安装不安装 mpi4py。pip install atst-tools 的元数据不含 mpi4py；pip install "atst-tools[parallel]" 是唯一文档化的 image-parallel 依赖路径。
R5MPI 文档说明 image parallel 仅用于外部启动的 NEB/AutoNEB，要求 mpi4py 与用户 site MPI/launcher/ABACUS MPI 一致，并提供无 SAI 专名的预检与从源码重装命令。用户文档与运行时错误均不含 SAI module、partition 或 ABACUS LTS 专名；包含 from mpi4py import MPI 与两 rank launcher 预检。
R6串行和非 image-parallel 工作流即使使用默认 NEB/AutoNEB schema，也不得要求 mpi4py 导入。单进程 dry-run 与 unit suite 在无 mpi4py 环境通过；MPI launcher 才给出缺少 mpi4py 的可诊断错误。
R7SAI 仅作为维护验证环境保留在 docs/developer/EXAMPLE_VALIDATION_OPERATIONS.md、reports 和 AGENTS 的维护段落；用户文档只描述通用 scheduler/MPI/后端责任。对 README、docs/index、docs/user、examples/README 的站点专名扫描为空；维护文档仍保留历史证据。
R8纠正已发现的版本与分支事实漂移，并让 AGENTS 以“维护验证环境”而非用户运行前提描述 SAI。USER_GUIDE 为 2.2.3；2.2.3 release notes Compatibility 为 2.2.3；atst-cli skill 不再宣称 main 是 v1.5 legacy。
R9链接、安装档位和事实版本拥有可维护的回归断言，不依赖人工浏览发现错误。相关 unit/docs-governance tests 断言绝对 PyPI 入口、主仓 URL、extras、无 SAI 用户入口与错误消息契约。

决策与备选

确认决策：不建设文档站。GitHub 是唯一规范源和协作入口；Gitee 是由维护者手动从 GitHub 拉取的只读镜像；PyPI 是唯一 Python 包发布入口。Markdown 原件继续在本仓维护。README 同时提供 GitHub 与 Gitee 的绝对用户文档入口，解决 PyPI 无法解析相对链接的问题；两边展示同一份 README，不维护镜像专属文本或代码。

确认决策：保留一个 atst-tools distribution 与 [parallel] extra。默认安装代表串行档；image-parallel 是显式 opt-in。MPI ABI 风险由文档化的 site-compatible 安装与预检处理，不通过发明 ATST MPI wheel 或第二套包名处理。

拒绝的备选：双向 GitHub/Gitee 同步会制造冲突和权威歧义；独立文档站增加部署与版本同步面；将 mpi4py 设为默认依赖会扩大串行用户的失败面；删除所有 SAI 记录会损失可审计验证证据。

入口与责任边界

规范内容：本仓 Markdown（main）
      |                     |
GitHub 主仓（协作权威）    Gitee 镜像（只读浏览/clone）
      |                     |
      +---- README 相对导航 -+
                 |
PyPI README ----绝对 GitHub/Gitee 用户指南与示例链接

安装：atst-tools → Serial 默认（无 mpi4py）
      + [dp] → DeePMD-kit
      + [parallel] → 仅外部 launcher 的 image-parallel NEB/AutoNEB

用户文档只拥有产品接口、后端前提与通用启动责任：ATST 不替用户提交 scheduler 作业，也不决定 site MPI。维护者文档拥有 SAI module、队列、作业和历史运行证据。运行时代码只在检测到外部 MPI launcher 时导入 mpi4py；错误信息指向“加载同一站点 MPI、使用该 mpicc 重装”的通用动作，不能假设任何特定平台。

预期实施范围：README.md、docs/index.md、docs/user/USER_GUIDE_CN.md、docs/user/CONFIG_REFERENCE.md、docs/user/PYTHON_API_REFERENCE.md、docs/user/ABACUSLITE_WRAPPER_GUIDE.md、examples/README.md、AGENTS.md、docs/skills/atst-cli/SKILL.md、docs/releases/RELEASE_NOTES_2.2.3.md、src/atst_tools/utils/mpi.py 与对应 tests。镜像通过同一 Git history 的维护者手动拉取同步；本实施不创建 fork 专属正文、配置或自动化。

失败处理

情形用户可见行为恢复
从 PyPI 点击仓库相对链接实施后不再把主入口设计为相对链接；绝对入口可直接定位平台文档。保留 GitHub/Gitee 双入口；回归测试阻止相对主入口复发。
默认安装后尝试外部 MPI image parallel明确报缺少 mpi4py 和 image-parallel extra，而非静默串行或崩溃。安装 [parallel]；再做 MPI 预检。
mpi4py wheel 与站点 MPI 不兼容错误不引用 SAI；说明 launcher/MPI ABI 需一致。加载站点 MPI，以其 mpicc 通过 --no-binary=mpi4py、--no-cache-dir 重装，再运行预检。
镜像暂时落后同一 README 始终将协作入口指向 GitHub；镜像不承担发布或协作职责。维护者按既有手动拉取方式恢复同步；不接受镜像侧修复或发布。

测试与验收

  1. 文档静态检查：git diff --check -- README.md docs examples/README.md AGENTS.md 与冲突标记扫描通过。
  2. 治理检查：python scripts/check_docs_governance.py 通过，并登记本 SPEC。
  3. 包元数据：扩展 tests/unit/test_package_metadata.py，断言默认 dependencies 无 mpi4py、parallel extra 仍为 mpi4py；测试一个无 mpi4py 的串行 dry-run。
  4. MPI 错误契约：扩展 MPI helper/API tests，断言 launcher 下缺依赖的错误包含通用恢复说明、没有 SAI 专名；既有 opt-in real-launcher suite 继续覆盖多 rank 同步失败。
  5. 入口契约：扩展 docs/example tests，断言 README 有 GitHub/Gitee absolute entry links、活跃用户文档无旧 clone URL/旧 release 标注/SAI 专名，并检查目标路径存在。
  6. 渠道人工验收：从 GitHub、Gitee 与 PyPI 渲染页各点击一次用户指南和示例入口；三者均到达预期的 main 文档。

实施与发布

  1. 先修复事实漂移和 README 分发入口；维护者按既有手动方式拉取镜像，并人工确认 PyPI 展示的最新 README。
  2. 接着整理串行/MPI 安装矩阵、通用预检与 utils/mpi.py 错误文案，新增回归测试。
  3. 最后仅重分类 AGENTS 的 SAI 段落与 atst-cli skill 的过时分支说明；维护者 SAI 操作/报告不改写为用户文档。
  4. 这是向后兼容的文档、诊断和测试增强；不改 YAML、CLI 名称或 API。按仓库版本规则可作为当前 patch 系列的兼容修订，在 release notes 说明零接口破坏。

风险与开放项

风险：GitHub 与 Gitee 的绝对链接会随 owner/默认分支迁移而需更新；用入口测试和单向镜像状态检查降低风险。site MPI 生态无法由 ATST 自动统一，因而只承诺清晰的 preflight、错误与 source-build 路径，不承诺任何 wheel 可在所有集群运行。

已关闭的设计项：用户已确认“无独立文档站、GitHub 规范源 + Gitee 只读镜像 + PyPI 包分发、双绝对入口、保留 extras”策略。本 SPEC 无阻塞开放决策；批准后应进入实施计划，不应直接在设计阶段修改产品行为。

本地 HTML SPEC 是本主题的规范源；GitHub/Gitee/PyPI 页面均为用户分发渠道，不反向修改本规范。
