概述

过渡态端到端验证暴露出 Sella 在 vendored abacuslite 上 2 步提前返回：sella 试探步后 atoms.get_forces() 返回的力（0.0374）与 ABACUS running log 末帧实际力（0.338）不一致，导致收敛判定使用错误力。该力读取架构（累积多帧 running log + read_abacus_out()[-1] 取末帧）在 abacus-develop 上游 abacuslite 中同样存在——问题属 abacuslite 本体，非 sella 上游，也非 atst-tools 引入。

同时核对确认（2026-08-04 审查修正，与快照引入史三阶段对应）：vendored 快照于 2026-05-10 引入（881a926）；drift-check CI 于 2026-07-06（7a04854）钉扎 762919f6（#7588 PR head）；当前基线 70f7ed69 是上游 2026-07-22 的 commit，于 2026-07-23（b8556c7）写入 CI。#7588（2026-07-06 合入）是基线 70f7ed69 的祖先——vendored 已含 #7588 加固。对上游 develop tip 实测 drift checker：零上游侧欠账，仅报 fork 侧 efermi 容错两处未登记 diff。且 abacuslite 不在 PyPI、SIF/本地运行时永远走 vendored 快照（external 分支是死代码）。

本设计确立跨仓维护模型：本仓（atst-tools）维护为主 → 收敛后向 abacus-develop 上游同步 → 阶段性拉取上游关键更新；并先修复力读取一致性（覆盖 md/relax/sella/ccqn 四条计算路径），建立可记录的同步纪律，收敛后把修复贡献回上游。

核心问题与修复方案

核心问题（一句话）

abacuslite 在返回力时可能拿到别的结构的力：当同一个工作目录里多次调用 ABACUS 时，它无条件取 running log 的"最后一帧"力，而最后一帧不一定是当前结构的力——sella 用这个错误力判断收敛，于是误判已收敛、1-2 步就提前停止。

为什么会这样（机制）

  1. abacuslite 每次 get_forces() 都在同一个目录里跑一次 ABACUS，ABACUS 把每次计算的结构和力追加到同一个 running_scf.log 文件（多帧累积）。
  2. abacuslite 读力时无条件取最后一帧（read_abacus_out()[-1]）。
  3. sella 的每一步内部会做试探步（以及初始 Hessian 的有限差分位移），这些都会向 running log 追加新帧；当"最后一帧"是试探点/位移点的力、而不是当前结构的力时，sella 就拿错了力。

实证数字：sella 试探步后读到力 0.0374（小于收敛阈值 0.1 → 误判"已收敛"），而 ABACUS 实际输出的力是 0.338——读错了帧。

为什么 md / relax / ccqn 没炸

  • ccqn 用自己的循环、逐帧读力的一致性更强 → 未触发。
  • relax / md 在 atst-tools 里是 ASE 逐帧驱动（每次调用追加一帧）→ 通常不触发。
  • 问题最容易被 sella 这类"一次调用内多次试探/位移"的优化器放大——这也是为什么只有 sella 暴露出来。

为什么 sella 会导致"最后一帧不为当前结构"（2026-08-04 确认）

已确认的机制链（代码层）：

  1. sella 一步内发起多次 ABACUS 力计算（sella 上游标准行为）：试探步 kick（set_x(x0+dx) → eval()）一次；初始/周期 Hessian 的有限差分位移（NumericalHessian(self._calc_eg, ...)，对每个位移点 set_x(x) → eval() → restore()）多次。这些调用复用同一个 abacuslite 目录，全部追加到同一个 running_scf.log。
  2. abacuslite 读力无条件取最后一帧（read_results → read_abacus_out(...)[-1]），不校验该帧是否属于当前结构。
  3. 两者叠加：sella 场景下 running log 末尾追加的是内部试探/位移计算的帧，而 abacuslite 把"最后一帧"的力当成当前结构的力返回。

实证（sella_repro）：试探步后 atoms.get_forces()（读回缓存）= 0.0374，同一时刻同一文件 read_forces_from_running_log(...)[-1] = 0.338——两者基于同一 parser 与同一文件，却不同，说明读回缓存的力与文件末帧力不一致（读路径把旧结构的力当成了当前结构的力）。

已排除的假设：若分歧只是"最后一次 ABACUS 调用有 trajectory 帧但无 TOTAL-FORCE 块"，read_abacus_out 的 len(trajectory) == len(forces) 断言会直接崩溃，而实测是成功返回 0.0374——因此该"部分缺块"形式不成立。但"末次调用整体未产新帧（SCF 未收敛仍正常退出）"（(b')）是另一候选，长度断言全部通过、[-1] 静默返回上一结构力，与观测相容。

待 Phase 0 用 SAI 实际 running log 一锤定音的精确分歧点（三候选）：

  • (a) 帧错位：read_abacus_out 的 trajectory/forces 子列表等长但内容错位（zip 配对把旧结构的力配给了当前结构）。
  • (b') 末次调用未产新帧：末次 ABACUS 调用 exit 0 但未新增任何帧（SCF 未收敛仍正常退出/试探点提前终止），[-1] 静默返回上一结构力。
  • (c) 读入后日志增长：缓存读入后又追加了帧（读入与读取之间存在一次未入缓存的 ABACUS 写入/时序问题）。

定位：分歧点落在 abacuslite 读路径（帧选择/对齐），被 sella 的多帧写入模式放大；Phase 0 的 SAI 日志核对即为此设计。

修复方案（一句话）

读力时不再无条件取"最后一帧"，而是取"结构坐标与当前结构一致的那一帧"（当前结构 = 本次写入目录的 STRU）；找不到匹配帧就报错（fail-closed），绝不静默返回错误结构的力。

修复边界（防止误伤正常功能）

  • 坐标校验只对 scf 启用（单帧-单次调用语义：每次 get_forces = 一次 ABACUS scf = 追加一帧）。
  • ABACUS 原生 relax / md（一次调用内部多 ion-step，末帧 = 最终结构而非写入的初态）与 MD 最新格式（running log 无坐标，走 MD_dump）显式绕过校验，按既有末帧语义读取。
  • 坐标比较带绝对 Å 容差（按 running log 坐标打印精度推导，见架构节 P3 ③），防误报。

目标与非目标

目标

  • 修复 vendored abacuslite 力读取一致性问题：read_abacus_out 返回的末帧力必须属于当前结构（fail-closed，不允许静默返回错误力）。
  • md/relax/sella/ccqn 四条 ASE 调度路径均覆盖修复与回归（golden-file 多帧 running log 测试，不依赖真实 ABACUS）。
  • 建立可记录的跨仓维护机制：基线 SHA 下沉到 vendored 树内、语义补丁清单显式登记、drift gate 语义明确（未登记新 drift 报警）。
  • 收敛后把 atst 语义补丁（efermi、band parser tolerance、力读取修复）贡献回 abacus-develop，合并后推进基线，使本地与上游收敛而非永久分叉。
  • 与既有机制衔接：复用并扩展 scripts/check_abacuslite_snapshot.py 与 CI workflow，不另起炉灶。

非目标

  • 不重写 abacuslite 核心架构（不做 per-call 目录隔离等大改，除非 SAI 诊断证实必要）。
  • 不立即切换到 install-from-source（external 模式）或等待 abacuslite PyPI 发布；这些是同步循环成熟后的长期目标。
  • 不修改 ASE 核心；不改 GenericFileIOCalculator 的公开调用契约。
  • 不把过渡态工具（NEB/AutoNEB/Sella/CCQN/d2s）的其他功能改动纳入本设计。

决策与备选

D1 后端模式：维持 vendored-only 作为当前唯一运行后端；_load_abacuslite_backend 的 external 分支保留（标注"预留"），不删除——它是将来 install-from-source / PyPI 发布后的真实通道。

D2 基线锚点：上游基线 SHA 从 CI env 下沉到 vendored 树内（ABACUSLITE_SNAPSHOT.md，记录三段历史：881a926/762919f6/70f7ed69），让 drift 比较与再同步有锚点；CI 从该文件解析 SHA（单一事实源，P6）。

D3 补丁清单：语义补丁显式登记（PATCHES.md，文件级/块级白名单，checker 归一化）；结构适配保持机械归一化。当前 efermi drift 即"未登记语义补丁"活例，修法：先登记、后上游化。补丁清单是解锁 CI 的前置（P1）——当前 CI 对自己钉扎的基线即 exit 1（efermi 未登记），且直推 main 绕过 PR-only gate。

D4 拉取触发：发布 atst-tools patch / 支持新 ABACUS 版本 / 上游出现新加固时，对最新上游跑 checker，合并真实上游修复、更新基线 SHA——非持续追踪。当前零上游侧欠账（#7588 已在基线内，E2 修正），仅欠 efermi 登记。

D5 贡献回路：收敛后语义补丁 PR 回 abacus-develop；合并后推进基线、再同步 vendored，本地与上游收敛。

D6 文档对齐：把"vendored 是 2.0.x 临时兜底"的旧表述改写为"本仓为主 + 定期同步 + 长期退位 vendored"；含 HANDOVER backend 小节与 DOCUMENTATION_STATUS_REPORT.md 账本（P8）。

D7 帧选择落点（P2/P4）：帧选择上提到唯一汇聚点 AbacusTemplate.read_results（core.py），scf-only，一次覆盖 legacyio/latestio 双后端；不改 read_abacus_out 签名（它还有 calculator 之外消费者 utils/abacus_io.py、workflows/md.py）。

D8 CI 触发（P1）：workflow 补 push: branches: [main]（或独立 drift 巡检 job），杜绝直推 main 绕过 gate。

备选与排除

  • 纯上游先行：拒绝。abacuslite 未发布、SIF 用 vendored，上游先行会无限期阻塞（efermi 已证明：只修上游则 SIF 至今仍坏）。
  • 立即切 install-from-source：拒绝。SIF/CI 变更面大，且上游同步循环尚未成熟；作为 D4/D5 循环的长期结果，不作为本设计前置。
  • 永久 fork（放弃上游同步）：拒绝。违背"尽可能不重写、ASE-native、消费上游"的既有哲学，长期维护成本高。
  • per-call 目录隔离 / 截断 running log：暂缓。改动面大、影响 restart/续算语义；仅在 SAI 诊断证实坐标校验不足时再评估。
  • 改 read_abacus_out 签名加 expected_coords：拒绝。污染纯解析语义且需改两个 IO 后端签名（P2/P4）；帧选择放 read_results 即可。

架构与数据流

力读取修复（Phase 1）

abacuslite AbacusTemplate.read_results(directory)   # 唯一汇聚点（D7）
  → 若 calculation == 'scf'（单帧-单次调用语义）:
      expected_coords ← read_stru(directory/'STRU') 的当前结构坐标   # 本次 write() 落盘
      frames ← read_abacus_out(running_*.log, sort_atoms_with=atomorder)   # 签名不变
      帧选择 ← frames 中"坐标(与帧同排列) == expected_coords 的最后一帧"    # 核心改动
      无匹配帧 → 抛明确错误（fail-closed，含 log 路径/帧数/坐标差异摘要）
      → SinglePointDFTCalculator(forces=该帧力, ...)
  else:   # 原生 relax/md 与 MD_dump 路径（R2）保持既有 [-1] 语义，不做坐标校验

落点与双后端（P2）：帧选择在 core.py::read_results 内完成，read_abacus_out（legacyio / latestio 两个实现）签名与纯解析语义不变；一次覆盖 LTS 3.10.1 → legacyio（SAI/SIF 生产路径）与 ≥3.11 → latestio 双后端。expected_coords 取自本次 write_input 落盘的 STRU（read_stru(directory/'STRU')），不依赖 ASE 侧 atoms 缓存，避免与 sella set_x/restore 缓存交互耦合。

坐标比较细节（P3）：① STRU 以物种分组序写出（write_stru(atoms[ind])），而 read_abacus_out 帧已按 self.atomorder 重排回 ASE 序——比较前统一到同一排列（建议：对 expected_coords 按分组序重排后与帧比较，或在重排前比较）；② running log 坐标系可为 DIRECT 或 CARTESIAN，比较前统一换算到 Cartesian Å；③ 绝对 Å 容差（以 running log 坐标打印精度推导，如 1e-4 Å 量级），"相对 1e-5"对分数坐标无意义。

fail-closed 作用域（2026-08-04 审查补强，防止误伤正常功能）：坐标校验仅适用于scf 计算类型（每次 get_forces = 一次 ABACUS scf 调用 = running log 追加一帧）——这正是 atst-tools 消费方式（SCF / ASE 驱动 relax / sella / ccqn 均逐 ASE 步调用 scf），也即本问题的目标场景。以下两类必须显式绕过校验、按既有末帧语义读取，否则 fail-closed 会误伤正常功能：

  • ABACUS 原生多帧单次调用（calculation=relax/md 单次调用内部多 ion-step，末帧为最终结构而非写入 STRU 的初态）——仅当计算类型为 scf 时才启用坐标校验。
  • MD 最新格式（running log 无坐标，走 read_traj_from_md_dump）——按 R2 单独路径，不做坐标校验。

其他消费者（P4）：read_abacus_out 还有 calculator 之外消费者——utils/abacus_io.py::_parse_last_abacus_frame（[-1] 语义正确，事后摘要）与 workflows/md.py（MD 帧解析，硬编码 latestio import，legacy ABACUS 下是潜在 bug，另案记录）。帧选择不侵入 read_abacus_out，故两者默认行为不变。

golden 夹具一次性消费（P5）：latestio read_abacus_out 读后 unlink() eig_occ.txt——多帧金样若走完整 latestio 读取，须提供与帧数一致的 eig_occ.txt 且注意重复读取需重建文件。

错误处理

  • 帧不匹配（read_results，scf-only）：无"坐标 == 当前结构"帧时抛明确错误（含 running log 路径、帧数、期望/末帧坐标差异摘要），调用方可见，不静默返回错误力。
  • 未登记 drift（P1 现状）：checker 当前对自己钉扎的基线即 exit 1（efermi 未登记），且 PR-only 触发被直推 main 绕过——补丁清单登记 + push 触发是解锁 CI 的前置。
  • 上游同步冲突：本地语义补丁与上游改动重叠时，以补丁清单 review 人工裁决（先合上游、再重放本地补丁）。
  • Phase 0 子机制判定：(a) 帧错位 / (b') 末次调用 exit 0 未产新帧 / (c) 读入后日志增长 三候选，以取证清单区分（见测试节）。

风险与开放项

风险：力读取不一致的精确子机制需 SAI 日志确认——若坐标校验不足（如 running log 末帧坐标本身与 STRU 一致但力块内容错位），需升级为解析对齐修复；上游 PR 合入周期不可控，可能长期以"已登记补丁"形态存在。

风险（fail-closed 误伤，2026-08-04 审查补强）：坐标校验若不加作用域，会误伤 ABACUS 原生多帧单次调用（calculation=relax/md）与 MD 最新格式（running log 无坐标）——正常功能被 fail-closed 阻塞。缓解：校验仅启用 scf 计算类型 + MD 走 MD_dump 单独路径 + 容差匹配（已写入 Phase 1 作用域规则）。

风险（审查新增，2026-08-04）：① P1 CI 现状——drift gate 对自己钉扎基线即红、直推 main 绕过 PR-only 触发；缓解：efermi 登记 + push 触发尽早先行；② P3 容差/排列——容差过紧 → 正常 scf false fail-closed、排列不一致 → 误判；缓解：绝对 Å 容差按打印精度推导、比较前统一排列、金样覆盖两侧；③ P7 (b')——若证实"末次调用未产新帧"，坐标校验无法区分"新帧缺失"与"尚未运行"；缓解：结合帧数单调性/调用序号（ION MOVE 头计数）补强，必要时退目录隔离评估；④ P4 md.py latestio 硬编码——legacy ABACUS 下潜在 bug，另案记录。

开放项：Phase 0 诊断结果将锁定 Phase 1 修法细节（坐标校验 vs 解析对齐 vs 截断/隔离）；补丁清单的具体登记格式（文件级/块级）在实施计划中按 checker 现状固定。
